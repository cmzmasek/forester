# Archaeopteryx demo trees

Small, synthetic phylogenies — one per feature — so you can **load a file and immediately try that feature**.
Open any file with **File → Open** in Archaeopteryx.

Almost all of these trees are made up (no real data, nothing to cite) and are deliberately shaped to show their
feature at its best; they are regenerated by `org.forester.demo.DemoTreeGenerator`. The one exception is
[`filoviridae-tree.xml`](filoviridae-tree.xml) — a **real** Ebola/Marburg virus phylogeny, included as a real-data
example. All of them are smoke-loaded by the test suite, so they stay in sync with the app.

| --- | --- | --- |
| [`size-by-property.xml`](size-by-property.xml) | **Size by property** | Left panel → **Size by: `read_count`**. Tip-symbol *area* is proportional to the value (honest scaling), so the deep-coverage isolates get visibly larger dots. |
| [`color-by-property.xml`](color-by-property.xml) | **Color by property** · **Search by field** | **Color by: `host`** for a distinct color per host category, or **Color by: `year`** for a blue→red numeric gradient. Its `host` (text) and `year` (numeric) properties also show off the **field-scoped search**: in a Search box on the left panel pick the field **`data:host`** and match e.g. *contains* `sapiens`, or pick the numeric field **`data:year`** and match e.g. `> 2015` or *range* `2010`–`2015` (the field selector lists only what this tree carries, and the operators switch to `= ≠ < ≤ > ≥ range` for numeric fields). |
| [`annotation-columns.xml`](annotation-columns.xml) | **Annotation columns** | **Tools → Annotation Columns…** and add `host`/`segment` (color strips), `viral_load` (heat map or bar) and `clade` (text) as tip-aligned columns. Also works in a **vertical orientation** (Settings → Display → Orientation: Root at Top/Bottom), where the columns become tip-aligned bands below the dendrogram — a **clustergram**. Add **Settings → Display → Tip Labels Below Columns** to move the sample labels below the grid so the tree sits directly on it. In the **Circular** layout the columns become concentric **rings** around the tree (colour-strip / heat-map cells as arc segments, bars grown radially, text as radial labels — the iTOL dataset-ring look); click a ring to show its colour key. |
| [`symbol-columns.xml`](symbol-columns.xml) | **Symbol columns** (binary / presence-absence) | **Tools → Annotation Columns…** and add the categorical `resistant` and `host` fields with the **Symbol** render type — each tip's value becomes a centred **shape mark** instead of a filled cell. A present value draws a **filled** mark, an explicit `no`/`absent`/`0`/`false` value a hollow **outline**, and a missing value **nothing** — a presence/absence (binary) mark column (`resistant` = yes / no / untested). A many-valued categorical field (`host`) becomes distinct **colored marks**. The marks are coloured by value from the same palette as **Color by**; click the column header to show the colour key. Also works in a **vertical orientation** and in the **Circular** layout (a mark centred in each tip's ring cell). Also in **File → Demo Trees → Symbol Columns**. |
| [`colorize-by-rank.xml`](colorize-by-rank.xml) | **Colorize / annotate clades by taxonomic rank** | **Tools → Colorize Subtrees via Taxonomic Rank…** (or **Annotate Clades by Rank…**) at rank **order**. Each **tip** carries its order as an in-tree rank annotation (the species is the node name), so it works with **no internet lookup**. The Carnivora clade root is deliberately **mis-annotated** `Rodentia` — the cats still colorize as Carnivora because **a tip's own identity wins** over a wrong/partial internal annotation. The clade **boxes / bars / brackets** also work in a **vertical orientation** (root at top/bottom), where they become horizontal marks below the tips, and in the **Circular** layout, where they become polar **annular sectors / arcs / brackets** around the tree (the iTOL clade-highlight look). Tick **"Also write the clade taxa into the tree"** in that dialog to **persist** each clade's taxon (name + rank + NCBI id) onto its internal node's `<taxonomy>` — an undoable edit that saves with the tree (so a later Colorize/Annotate, or another tool, sees the enriched internal taxa); the same writer ancestral-taxonomy inference uses. |
| [`infer-ancestor-taxonomies.xml`](infer-ancestor-taxonomies.xml) | **Infer ancestor taxonomies** | Six real, well-known species at the tips (`Homo sapiens`, `Pan troglodytes`, `Mus musculus`, `Rattus norvegicus`, `Felis catus`, `Canis lupus`); the internal nodes carry no taxonomy. **Analysis → Infer Ancestor Taxonomies** (accept the online resolve) assigns each internal node the deepest taxon its descendants share (e.g. Murinae, Carnivora, Boreoeutheria) with ranks + NCBI tax-ids where defined, so you can then **Colorize / Annotate Clades by Rank** on the inferred internal taxa. *Needs an internet connection for the resolve* — a tip's lineage is not stored in phyloXML, so it cannot be inferred offline. After the resolve, **collapse** a clade (click its node) and its triangle is labelled with the clade's **common taxon** (the deepest taxon all its tips share, e.g. "Carnivora (3)") instead of the boundary tip names — so you can tell what a collapsed clade *is* at a glance. Turn on **Settings → Display → Internal Taxonomy Key** for a draggable key summarising the inferred internal taxa grouped by rank ("order: … | family: …") with counts — the taxonomic backbone at a glance. |
| [`filoviridae-tree.xml`](filoviridae-tree.xml) | **Real virus data · color by species** | **The one real dataset here** — a filovirus (Ebola & Marburg) protein phylogeny (MAFFT + FastTree), 13 representative viruses. Opens **colored by species** (`repseq:species`): the Ebola species (*Orthoebolavirus zairense* = Zaire/EBOV, *sudanense*, *restonense*, *bundibugyoense*, *taiense*, *bombaliense*), *Orthomarburgvirus marburgense*, and *Dianlovirus*. Each tip carries **taxonomy** (scientific name + rank), **bootstrap support** on the branches, per-protein **NCBI accessions** (NP, L, GP, VP35, VP40, VP30, VP24), and `repseq:` metadata — **host** (*Homo sapiens*, *Rousettus* & *Mops* bats), **country** (Uganda, Sierra Leone, Côte d'Ivoire, Kenya, China), **year**, **strain**. Try **Color by → `repseq:host`** or **`repseq:country`**, or **Tools → Annotation Columns** with `species` / `host` / `country` / `year`. Also in **File → Demo Trees → Filoviridae (Ebola & Marburg)**. |
| [`bat-phylogeny.xml`](bat-phylogeny.xml) | **Rich taxonomy · colorize by rank** | A larger, **34-species** tree of the bats (order *Chiroptera*) spanning both suborders and eight families. Also in **File → Demo Trees → Bat Phylogeny (Taxonomy by Rank)**, which opens it colorized by family. Schematic (illustrative branch lengths), not a rigorous phylogeny. |

It **auto-detects as a time tree**; turn on **Settings → Overlays → Time axis: Geologic** to draw the ICS geologic scale (the pika/rabbit split is Eocene, the *Lepus* radiation Pliocene). Every tip carries a common + scientific name and every internal node is dated and annotated with its clade + rank (order *Lagomorpha*; families *Leporidae*, *Ochotonidae*; genera *Lepus*, *Sylvilagus*), so **Colorize / Annotate Clades by Rank** works offline. | [`scale-axis.xml`](scale-axis.xml) | **Scale axis** | **Settings → Display → Scale Axis**. A labeled distance axis with tick marks runs along the bottom (branch lengths in substitutions/site), so you can read a tip's distance off the axis directly. It **floats**: zoom in and the axis stays pinned to the bottom of the view so it never scrolls out of sight, while exports anchor it at the tree's base. Also works in a **vertical orientation** (root at top/bottom), where it becomes a labeled ruler down the side. | [`long-branch-break.xml`](long-branch-break.xml) | **Break long branches** | **Settings → Layout → Break Long Branches**. The ingroup branches are ~0.1–0.3 substitutions/site, but one distant, **fast-evolving outgroup** sits on a ~4.0 branch that squashes the rest to an unreadable sliver. Turn the option on: the outgroup is drawn **shortened with a break mark** (`─//─`) and the informative part of the tree **reclaims the freed width** — the depth scale is re-derived from the capped height. Display-only: the true branch length is unchanged (turn on **branch-length values** to see the real 4.0). A branch is treated as "long" when it exceeds 8× the median branch length, so a well-behaved tree shows no breaks. The internal nodes carry **bootstrap support** (shown clear of the break mark). Also in **File → Demo Trees → Break Long Branches**. |

Undoable. An incomplete date maps to the interval midpoint; an ambiguous `D/M` vs `M/D` is read day-first (with a toggle). |

## Adding a demo tree

When you add a new feature, add its demo here:

1. Build the tree in `org.forester.demo.DemoTreeGenerator` (a small method named after the feature) and rerun it
   from the repo root: `java -cp forester/java/classes org.forester.demo.DemoTreeGenerator`.
2. Name the file after the feature (kebab-case, e.g. `size-by-property.xml`). Reuse an existing tree's data shape
   when it already fits rather than duplicating it.
3. Add a shape check to `org.forester.archaeopteryx.DemoTreesTest` (so the file can't silently rot), and ideally
   load it in the feature's own test too.
4. Add a row to the table above.
