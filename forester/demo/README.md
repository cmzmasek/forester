# Archaeopteryx demo trees

Small, synthetic phylogenies — one per feature — so you can **load a file and immediately try that feature**.
Open any file with **File → Open** in Archaeopteryx.

All trees here are made up (no real data, nothing to cite) and are deliberately shaped to show their feature at
its best. They are regenerated by `org.forester.demo.DemoTreeGenerator` and smoke-loaded by the test suite, so they
stay in sync with the app.

| File | Feature | How to demo |
| --- | --- | --- |
| [`size-by-property.xml`](size-by-property.xml) | **Size by property** | Left panel → **Size by: `read_count`**. Tip-symbol *area* is proportional to the value (honest scaling), so the deep-coverage isolates get visibly larger dots. |
| [`color-by-property.xml`](color-by-property.xml) | **Color by property** | **Color by: `host`** for a distinct color per host category, or **Color by: `year`** for a blue→red numeric gradient. |
| [`annotation-columns.xml`](annotation-columns.xml) | **Annotation columns** | **Tools → Annotation Columns…** and add `host`/`segment` (color strips), `viral_load` (heat map or bar) and `clade` (text) as tip-aligned columns. Also works in a **vertical orientation** (Settings → Display → Orientation: Root at Top/Bottom), where the columns become tip-aligned bands below the dendrogram — a **clustergram**. Add **Settings → Display → Tip Labels Below Columns** to move the sample labels below the grid so the tree sits directly on it. In the **Circular** layout the columns become concentric **rings** around the tree (colour-strip / heat-map cells as arc segments, bars grown radially, text as radial labels — the iTOL dataset-ring look); click a ring to show its colour key. |
| [`colorize-by-rank.xml`](colorize-by-rank.xml) | **Colorize / annotate clades by taxonomic rank** | **Tools → Colorize Subtrees via Taxonomic Rank…** (or **Annotate Clades by Rank…**) at rank **order**. Each **tip** carries its order as an in-tree rank annotation (the species is the node name), so it works with **no internet lookup**. The Carnivora clade root is deliberately **mis-annotated** `Rodentia` — the cats still colorize as Carnivora because **a tip's own identity wins** over a wrong/partial internal annotation. The clade **boxes / bars / brackets** also work in a **vertical orientation** (root at top/bottom), where they become horizontal marks below the tips, and in the **Circular** layout, where they become polar **annular sectors / arcs / brackets** around the tree (the iTOL clade-highlight look). Tick **"Also write the clade taxa into the tree"** in that dialog to **persist** each clade's taxon (name + rank + NCBI id) onto its internal node's `<taxonomy>` — an undoable edit that saves with the tree (so a later Colorize/Annotate, or another tool, sees the enriched internal taxa); the same writer ancestral-taxonomy inference uses. |
| [`infer-ancestor-taxonomies.xml`](infer-ancestor-taxonomies.xml) | **Infer ancestor taxonomies** | Six real, well-known species at the tips (`Homo sapiens`, `Pan troglodytes`, `Mus musculus`, `Rattus norvegicus`, `Felis catus`, `Canis lupus`); the internal nodes carry no taxonomy. **Analysis → Infer Ancestor Taxonomies** (accept the online resolve) assigns each internal node the deepest taxon its descendants share (e.g. Murinae, Carnivora, Boreoeutheria) with ranks + NCBI tax-ids where defined, so you can then **Colorize / Annotate Clades by Rank** on the inferred internal taxa. *Needs an internet connection for the resolve* — a tip's lineage is not stored in phyloXML, so it cannot be inferred offline. After the resolve, **collapse** a clade (click its node) and its triangle is labelled with the clade's **common taxon** (the deepest taxon all its tips share, e.g. "Carnivora (3)") instead of the boundary tip names — so you can tell what a collapsed clade *is* at a glance. |
| [`scale-axis.xml`](scale-axis.xml) | **Scale axis** | **Settings → Display → Scale Axis**. A labeled distance axis with tick marks runs along the bottom (branch lengths in substitutions/site), so you can read a tip's distance off the axis directly. It **floats**: zoom in and the axis stays pinned to the bottom of the view so it never scrolls out of sight, while exports anchor it at the tree's base. Also works in a **vertical orientation** (root at top/bottom), where it becomes a labeled ruler down the side. Its branch lengths also make it the **circular phylogram** example: switch to the **Circular** type with **Draw Phylogram** on and the tips fan out by distance-from-root, with concentric distance rings (turn on **Scale**). |
| [`beast-annotations.nex`](beast-annotations.nex) | **BEAST / BEAST X output** | A small time-calibrated NEXUS tree with FigTree-style `[&…]` annotations. **File → Open** it: `posterior`, node `height` + `height_95%_HPD`, and `rate` are parsed into structured data, so **posterior support values** show on the branches automatically, **Settings → Display → Node Age Bars (HPD)** draws each internal node's 95% age interval, and **Color by: `beast:rate`** renders the per-branch rate as a gradient. Handles BEAST, BEAST X and BEAST 2 / TreeAnnotator output — every other `key=value` field becomes a `beast:*` node property. |
| [`node-hpd-bars.xml`](node-hpd-bars.xml) | **Node age bars (HPD)** | View as a **phylogram**, then **Settings → Display → Node Age Bars (HPD)**. A dated (ultrametric) mammal tree (time in My); each internal node carries a phyloXML `<date>` age-with-interval, and shows a translucent bar spanning its 95% age interval. Also works in a **vertical orientation** (root at top/bottom), where the bars become vertical, and in the **Circular** layout (with **Draw Phylogram** on), where each bar becomes a translucent **radial segment** along the node's spoke spanning its age interval (turn on **Scale** for the distance rings to read ages against). |
| [`zebra-stripes.xml`](zebra-stripes.xml) | **Zebra stripes** | **Settings → Display → Zebra Stripes**. Faint alternating row bands make it easy to track a tip label across to its **Annotation Columns** (`host`, `reads`) on this wider 16-tip tree. Also works in a **vertical orientation** (root at top/bottom), where the bands become vertical (over alternate tip columns), and in the **Circular** layout, where they become alternating angular **wedges** (faint pie slices behind every other tip, out to its annotation rings). |
| [`reverse-tip-order.xml`](reverse-tip-order.xml) | **Reverse tip order** | **Settings → Display → Reverse Tip Order**. An 8-tip ladder (`tip_01`…`tip_08`); the toggle reverses the tip order (the staircase inverts) — display-only, the tree data is unchanged. In a root-top/bottom orientation the tips run sideways, so it flips them left↔right. |
| [`domain-architectures.xml`](domain-architectures.xml) | **Domain architectures** | View as a **phylogram**, then left panel → **Display Data: Domain Architectures**. A synthetic protein family; each tip carries a sequence with a Pfam-style domain architecture (SH3 / SH2 / Pkinase / PH / Ig / SAM boxes). Also works in a **vertical orientation** (root at top/bottom), where each tip's architecture becomes a vertical bar hanging off the tip (boxes only — the domain-name labels are shown in the root-left view). |
| [`import-annotations.xml`](import-annotations.xml) + [`import-annotations.csv`](import-annotations.csv) | **Import Annotations (CSV/TSV)** | Open the tree (12 plain-named tips `isolate_01`…`isolate_12`, no per-tip data), then **File → Import Annotations (CSV/TSV)…** and pick `import-annotations.csv`. Match the **`name`** column against **Tip name** — the preview shows *12/12 rows match* — and the `host` / `country` / `reads` columns are joined onto the tips. Now **Color by: `host`** (or `country`), or show **`reads`** as an **Annotation Column** / heat map. The dialog also lets you **override the delimiter**, **uncheck columns** to skip them, and **rename** a column to a different property. Also matches on sequence accession or taxonomy for tables keyed that way, and **File → Import Annotations from URL…** fetches a CSV published to the web (e.g. a Google Sheet). After importing, **File → Re-import Annotations** re-fetches the same source and re-applies the same mapping with one click — edit the CSV (add rows/columns) and pull the changes in without walking the dialog again. |
| [`heatmap-matrix.xml`](heatmap-matrix.xml) | **Heat-map matrix (clustergram)** | View as a **phylogram**, then **Tools → Annotation Columns…** and add `s1`…`s6` as **Heat map (matrix)**. All matrix columns share **one** color scale (so a cell's color is comparable across samples) and draw as a contiguous grid. Best in a **vertical orientation** with **Tip Labels Below Columns** — a proper clustergram (dendrogram over a shared-scale heat map). The shared color-scale legend shows automatically (drag to reposition; double-click to reset). |
| [`root-on-top.xml`](root-on-top.xml) | **Root-on-top / bottom orientation** | **Settings → Display → Orientation: `Root at Top`** (or `Root at Bottom`). A 12-tip vertebrate phylogram becomes a vertical dendrogram: tips fan along the bottom with **vertical (90°) tip labels** — switchable via **Tip label angle** to **Diagonal (45°)**, **Horizontal (0°)** (upright, centered under each tip — cleanest for short names), or **Auto (fit)** (upright when the names fit between tips, tilting to 45°/90° as they get denser) — while the bootstrap support and branch-length numbers stay **upright**. |
| [`search-emphasis.xml`](search-emphasis.xml) | **Emphasize search hits** | Search (box **a**) for `kinase` — four scattered tips match — then **Settings → Display → Bold Found Labels**, **Dim Non-Matches**, and/or **Pulse Found Nodes**. Hits go bold, the rest (names *and* their support / branch-length numbers) fade toward the background, and a gentle halo pulses around each hit. Bold + dim work in exports; the pulse renders as a static glow. With hits present, the left panel shows a **◀ _k_ / _N_ ▶** navigator (also **View → Find Next / Find Previous**, ⌘G / ⌘⇧G) that centers each hit in turn — a hit inside a collapsed clade scrolls to its triangle. |
| [`ancestral-pie-charts.xml`](ancestral-pie-charts.xml) | **Ancestral-state pie charts** | A synthetic BEAST phylogeography tree: each tip carries its single sampled location (`beast:location`), each internal node a posterior distribution over locations (`beast:location_set` + `beast:location_set_prob`). Left panel → **Ancestral pie: `location`** draws a pie at every node — wedges sized by state probability and colored from a shared state→color key, tips as solid single-state discs — with a draggable **state legend** (double-click to reset its position). The dropdown appears only for trees that carry such discrete-trait data. Works in a **vertical orientation** (root at top/bottom) too, and rides every export. The same posterior sets are produced by loading real BEAST discrete-trait / phylogeography output (see `beast-annotations.nex`). |

Combine features on one figure — e.g. open `color-by-property.xml`, then **Color by: `host`** *and* **Size by: `year`**
for a two-attribute (color + size) figure on a single tip symbol.

## Adding a demo tree

When you add a new feature, add its demo here:

1. Build the tree in `org.forester.demo.DemoTreeGenerator` (a small method named after the feature) and rerun it
   from the repo root: `java -cp forester/java/classes org.forester.demo.DemoTreeGenerator`.
2. Name the file after the feature (kebab-case, e.g. `size-by-property.xml`). Reuse an existing tree's data shape
   when it already fits rather than duplicating it.
3. Add a shape check to `org.forester.archaeopteryx.DemoTreesTest` (so the file can't silently rot), and ideally
   load it in the feature's own test too.
4. Add a row to the table above.
